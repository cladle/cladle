# 全種の台帳

Cladle の収録データの正本です。本家・ゲキムズ・魚編・鳥編・昆虫編は、どれもこの台帳から `tools/build_all.py` で作ります。1か所直せば全部のモードに届きます。

| ファイル | 中身 |
| --- | --- |
| `species.jsonl` | ゲキムズに入る全種。1行に1種。並びはゲキムズの出題の並び |
| `clades.jsonl` | 全部の節目（門・綱・目・科・属・クレード）。1行に1つ |
| `meta-main.json`, `meta-hard.json` | 本家とゲキムズの meta（出典・出題の設定など）。版番号と予約は data-*.json の側で決まる |
| `group_aliases.txt` | 別名に入れないグループ名（ウニ・カニなど） |
| `ledger.py` | 台帳を読み、確かめ、本家とゲキムズのデータを作る |
| `export.py` | 台帳を最初に作ったときのスクリプト（2026-11-02、本家 0.3.18 とゲキムズ hard-0.3.12 から） |

## 1行の形

種：

```json
{"id": "s2", "parent": "g_eptatretus", "ja": "ヌタウナギ", "sci": "Eptatretus burgeri", "jaStatus": "standard", "aliases": [], "fact": "大量の粘液を出して身を守る。", "tier": 2, "main": {"order": 22, "id": "nutaunagi"}}
```

- `parent`：入れる節目の id（ふつうは属 `g_…`）。
- `tier`：知名度（1〜4）。ゲキムズと番外編はこの値を使う。
- `aliases`（別名）・`sciSynonyms`（旧学名）・`subspeciesAliases`（亜種名）・`groups`（グループ名）・`verify`（要確認の印）などは `docs/SCHEMA.md` のとおり。

節目：

```json
{"id": "araneae", "parent": "euchelicerata", "ja": "クモ目", "sci": "Araneae", "rank": "目", "desc": "腹部の出糸突起から糸を出す。…", "main": {"order": 160}}
```

### 本家に出す印 `main`

`main` が付いた種・節目だけが本家に出ます。本家の木は、台帳の木から `main` の付いた節目だけを残したものです（間の節目はたたまれる）。

- `order`：本家での並び（今日の動物の選び方に入る）。新しく足すときは、いまの最大の値＋1 にする。
- `id`：本家での id が台帳の id と違うときだけ書く（共有リンクや成績のため、本家の id は変えない）。
- そのほかの欄：本家だけ違う値（例：`"tier": 2` は本家だけ知名度2）。`null` はその欄を本家では消す。

## よくある直し方

- **説明・和名を直す**：その行の `fact`（種）・`desc`（節目）・`ja` を書き換える。本家だけ違う値が `main` の中にあれば、そちらも見る。
- **種を足す**：`species.jsonl` の最後に、和名と学名だけの行を足せばよい。本家にも出すなら `"main": true` を付ける。
  ```
  {"ja": "ニホンウナギ", "sci": "Anguilla japonica", "main": true}
  ```
  `build_all.py`（github.dev ならコミットしたときの GitHub）が、学名の属名から属の節目を探して `parent` に入れ、`id`（h＋学名の英字）・`jaStatus`・`aliases`・`fact`（空）・`tier`（3）を埋め、本家の並びを最後にする。説明や知名度はあとから書き足す。属が台帳に無いときは止まるので、`clades.jsonl` に属の行（`parent` は科の id）を足す。
- **ゲキムズにいる種を本家にも出す**：その種の行に `"main": true` を足す。本家の木で見せたい節目（目・科など）にも `main` を付ける。
- **木の形を変える**：`parent` を書き換える。本家で新しい節目を見せるときは、その節目に入る群（科など）を、本家にいない種の群も含めて全部その下へ移す。移し忘れると `build_all.py` が知らせる（例：クモ目の下に Araneoidea を作ったのに、ほかのクモの科がクモ目の直下に残っている）。

直したら `python3 tools/build_all.py` で何が変わるかを見て、`--write` で data-*.json に書きます。

github.dev で直したときは、コミットするだけで構いません。GitHub（Actions の「check」）が代わりに `build_all.py --write` を動かし、書き出した data-*.json を同じブランチに「台帳から data-*.json を書き出す（自動）」としてコミットします。main に直接コミットしたときは、続けて公開ページも作り直されます。

ただし、もう始まっている版の種・節目・知名度を変えたときは、新しい版の名前と始まる日を決める必要があるので、自動では書き出さずに確認が × になります。そのときは `--new main=0.3.19@YYYY-MM-DD` のように版を決めて動かします（Claude に頼んでもよい）。

## 確かめていること

`build_all.py` は作る前に `ledger.py` の `check()` で、id の重なり、親の無い節目、種の無い節目、本家の根が1つか、グループ名の別名を確かめます。どれかがあれば止まります。
